# RVVIRC HOST — Telegram-бот

Python 3.12+, aiogram 3.13+, SQLite. Хранение: `rvvirc.db` (создаётся автоматически).

## Запуск
```bash
pip install -r requirements.txt
cp .env.example .env      # впишите BOT_TOKEN
python main.py
```
При первом запуске в консоли появится строка `ВЛАДЕЛЕЦ НЕ ПРИВЯЗАН ... /claim <код>`.
Аккаунт `@gottalarp` отправляет боту эту команду. Роль владельца записывается **по Telegram ID**
(нужны и код из консоли сервера, и совпадение username). Дальнейшая смена username ничего не даёт.
Команды для назначения новых владельцев нет вообще — владелец один, привязывается только через `/claim`.

## Что нужно сделать перед боевым запуском
1. **Каналы/чаты подписки**: бот должен быть администратором в каждом. Добавление: `/sub_add <chat_id|@канал> <ссылка> <название>`
   (для приватных чатов — числовой chat_id вида `-100…` и пригласительная ссылка). Бот сам проверит доступ при добавлении.
2. **Сайт**: реализовать API ниже и задать `SITE_API_URL`, `SITE_API_TOKEN`. Без этого регистрация/промокоды честно отвечают «сайт недоступен».
3. **Хостинг-панель**: в ТЗ не указана, поэтому драйвер не выдуман. Реализуйте подкласс `PanelAPI` (`integrations/panel_api.py`:
   `create_server`, `get_server`, `power`) по документации вашей панели и верните его из `get_panel()`.
4. Тарифы, лимиты, тексты: `/plan_set`, `/set`, `/settext` (или `texts.json`).

## Контракт API сайта (`Authorization: Bearer <SITE_API_TOKEN>`, JSON)
| Метод | Тело | Ответ |
|---|---|---|
| `POST /bot/v1/accounts/register` | `email, telegram_id, bot_user_id` (+`Idempotency-Key`) | `{status: created\|verification_sent\|rejected, account_id, email_verified, message}` |
| `POST /bot/v1/accounts/status` | `email, telegram_id` | `{account_id, email_verified}` |
| `POST /bot/v1/promo/apply` | `account_id, code, percent` | `{applied: bool, message}` |
| `POST /bot/v1/ip/block` | `cidr, hours, reason, admin` | `{ok}` |
| `POST /bot/v1/ip/unblock` | `cidr, admin` | `{ok}` |

Требования к сайту: пароли через Telegram не запрашиваются; если e-mail уже существует — сайт **не привязывает его молча**,
а шлёт письмо-подтверждение владельцу (`verification_sent`); `email_verified=true` только после перехода по ссылке.
Бот пишет «успех» только по ответу сайта. Промокод считается применённым только при `applied: true`.
IP-блокировки выполняет сайт по своим логам: бот IP пользователей не знает и нигде не хранит (в журнал пишется только CIDR, введённый админом).

## Роли
- **Техподдержка** (уровень 1): `/user`, статус подписок/рефералов/серверов, тикеты (`/tickets /ticket /reply /close /escalate`). Почта видна маской.
- **Помощник владельца** (уровень 2): поддержка + только те права, что владелец включил (`/perm <ref> <право> on|off`).
- **Владелец**: всё. Нельзя менять себя и владельца; админов трогает только владелец; `roles_assistant` — отдельное право.
- Пользователи ищутся по Telegram ID или `#внутренний_ID` (username для поиска и выдачи прав намеренно не используется).
- Все действия админов пишутся в `audit_log` (`/log`).

## Команды админки
`/admin` (кнопки-разделы показывают списки и подсказки), `/user`, `/ban /unban /bans`, `/ref_adjust`, `/reward`,
`/grant_support /grant_assistant /revoke /perm /admins`, `/promo_add /promo_edit /promo_toggle /promo_del /promo_info`,
`/sub_add /sub_toggle /sub_del`, `/set /texts /settext /plan_set /plan_del`, `/ipblock /ipunblock`, `/stats /log`.

Области блокировки: `account`, `free_server`, `referral_rewards`, `blacklist` (чёрный список по внутреннему ID; Telegram ID хранится отдельно в `users.tg_id`).
Блокировку по Telegram ID можно поставить и тому, кто ещё не запускал бота.

## Допущения и ограничения (честно)
- ТЗ в присланном файле обрывается на разделе 11; тикеты, правила и тексты доделаны по смыслу, правила — заглушка для редактирования.
- Реферал = новый пользователь (первый запуск по ссылке) + выполнил подписки. Один Telegram ID — один раз; самореферал невозможен.
  Мультиаккаунты одного человека бот определить не может (это есть в ТЗ).
- Реферал, отклонённый из-за блокировки (`rejected`), позже автоматически не пересчитывается — используйте `/ref_adjust`.
- FSM-состояния в памяти: после перезапуска бота диалог ввода (почта/промокод) нужно начать заново. Данные в БД сохраняются.
- Лимит промокода по тарифам/мин. сумме хранится и передаётся сайту в данных промокода; проверку заказа должна выполнять платёжная часть сайта.
- Код проверен компиляцией и тестами слоя БД; end-to-end с реальным Telegram, сайтом и панелью не запускался (нет доступа к ним).
